# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Product decisions

The user approved the four-tool scope and quality work on 2026-10-12.

- The core extension contains exactly Color Picker, Screenshot, CSS, and Video Speed. Keep environment navigation, site reset, environment settings, and the core Proxy consumer out of the product. Do not restore the environment side panel or its permissions.
- The approved site-aligned popup theme is the default implementation. Reuse shared colors, typography, and header tokens from `browser/shared/temoto-popup-tokens.css`; product-specific dimensions and feedback remain separate. Do not package study assets or query switches.
- The in-product core header is lowercase `temoto`; the separately installed product remains `temoto Proxy`. Store listing names stay unchanged.
- Both popups use a flat #080808 surface, visible 1px rules, off-white text and purple selection. Avoid translucent glass, rounded cards, and red/green/amber status colors. Express errors through clear text in neutral tones. Do not modify Proxy profile colors as part of core changes.
- Keep the Chrome popup 416px wide with a 60px header and content-sized height (up to 580px). The user removed the unused bottom rail and chose English-only UI on 2026-10-12. Do not reserve space for notifications or switch language based on the page, Chrome locale, or query string.
- The user simplified the layout on 2026-10-13. The launcher is four 68px rows with an icon and tool name, separated by 1px rules. Do not add feature descriptions, helper paragraphs, or empty history placeholders. Avoid separate card backgrounds, gaps, rounded corners, and status pills.
- Do not show success toasts for picking/copying colors, starting inspection, or capturing/copying/saving images. Show actual operation failures as persistent inline error text in the affected tool; clear it when retrying or changing tools. Keep useful in-progress capture state and actual video state.
- Keep the header compact with a single-line white `temoto` wordmark and no separate mark beside it. The core has no environment Settings entry. Do not add a persistent current-page/video strip or Proxy status to its home surface.
- Typography and SVG refinements must preserve the approved black/purple flat direction. Use locally bundled Geist Sans Variable for the UI, wordmark, and playback-rate numbers, with tabular numerals for rates. Keep IBM Plex Mono only for technical color values and capture dimensions. The popup and page video badges share `public/fonts/geist-latin-wght-normal.woff2`, with its license bundled. Page video badges attempt to load Geist and use an explicit system sans fallback when loading is unavailable or fails; do not claim Geist is applied without verifying the rendered font. Video font failure must not break speed controls or apply the font to the page's own content.
- Use consistent regular-weight Phosphor icons: 22px launcher, 20px tool header, and 18px actions. Place launcher icons beside the tool names at a 24px left inset. Keep product-specific typography refinements in core styles so they do not silently change Proxy.
- The user requested consistent control sizes across both extensions on 2026-10-13. Use shared tokens for 44px standard controls, 56px full-width action rows, 68px launcher/profile rows, and 13px/500 Geist control labels. Give adjacent actions equal columns; headers and value readouts retain their separate hierarchy. Use the same font family and brand tokens in popup, capture preview, and Proxy's inline editor.
- Both extension popups share `browser/shared/temoto-popup-tokens.css` colors, header and brand tokens while preserving independent dimensions, layouts and jobs. Do not change the independent Proxy runtime or configuration during core cleanup.
- Use the approved solid B/Joint mark from `browser/shared/temoto-mark.svg`; Proxy uses its inward hollow outline. Generate transparent #9974F8 PNGs through `browser/shared/icon-utils.mjs` and the existing icon command. Preserve the canonical 160px frame; only Proxy's 16px icon strengthens its inward stroke.
- Color Picker, Screenshot and Video Speed open their controls with a clear Back action. CSS starts page inspection directly from the launcher. Keep tool headers 60px high with a 60 × 60px Back target left of the divider and a small tool icon beside the title.
- Keep tool details to the controls themselves, using functional rows and visible 1px rules. Screenshot uses one row per capture type. Avoid oversized framed feature icons, rounded cards, and white floating primary buttons.
- Color Picker offers HEX, RGB and HSL copy plus the latest eight unique picked colors. Normalize history to uppercase six-digit HEX; a new pick moves an existing color to the front. Defaults and preview colors do not enter history until actually picked. Save history and format locally, and report clipboard failure honestly.
- Screenshot offers only Visible area and Full page, plus Fit/100% preview, clipboard image copy and PNG download. The user removed Select region and Capture options on 2026-10-13. Do not restore Delay or Force reveal preferences. Full-page preparation automatically scrolls to trigger lazy content, waits for images/fonts with a bound, and settles animations; retain page-state restoration on success and failure.
- CSS launch failures belong inside the CSS launcher row with a Retry action on that same row. Keep initialization and other-tool errors separate, clear the CSS failure when retrying or changing tools, and disable repeated launches while one is pending.
- Give each capture a separate local ID and retain its IndexedDB data so its preview can reload. The preview's Close action deletes that capture. Captures expire after one hour; remove expired records on the next capture save/load. Direct browser-tab closure does not guarantee immediate deletion.
- CSS inspection selects one element, shows its dimensions, margin, padding, typography, colors and borders, and copies grouped computed declarations. Keep unique-selector copy as a separate action. Do not describe computed styles as the original stylesheet or complete layout reconstruction.
- While CSS inspection is active, show a compact persistent guide for selection and Esc-to-exit, use a crosshair cursor, and remove overlays/listeners on exit or reinjection. Copy success must follow clipboard acknowledgement.
- Video Speed commands use 0.25–5×. The user removed the slider on 2026-10-13. Keep the four preset buttons and equal-width −0.05/+0.05 buttons. Page shortcuts remain `G` for 1× / 1.5×, `D` for +0.25× and `S` for −0.25×.
- Display each video's actual positive playback rate, including page-selected rates outside the control range. Popup state and pointer-transparent top-left badges follow rate changes and media replacement. Do not store a chosen speed to apply to later videos.
- Load local video shortcuts/badges automatically in every HTTP(S) frame. Ignore editable fields and modifier-key combinations, and clean up invalidated content scripts. Show video availability only on its launcher cell and tool controls when relevant.
- The hidden, explicitly opted-in WebMCP availability/video-speed bridge remains auxiliary to Video Speed. It does not add a launcher surface or expose captures, colors, preferences, or other tabs.
- Keep `temoto Proxy` independently installable and operated. Its broad Chrome proxy permission, popup editor, configuration and credentials remain solely in that product; the core does not request or display them.
- Keep local source, built QA, Store submission, and public release status distinct. Do not bump a version, overwrite a submitted ZIP, publish a website, or submit/release an extension merely because the source work is complete.
