# temoto Proxyの機能と使い方

**用意済みのプロキシやPACを、ポップアップだけで保存・切り替えるChrome拡張です。** 別タブの管理画面はなく、操作画面は英語です。

`temoto`本体とは別にインストールできます。切り替えはこの拡張を入れたChromeの通常ウィンドウ全体に影響し、ひとつのタブだけには限定されません。他のアプリやOSの接続設定は変更しません。

## ホームの操作

| 操作・表示 | 意味 |
| --- | --- |
| 右上の`+` | 新しい接続先を追加します。最初に選ぶ方式はFixed proxyかPAC URLです。 |
| プロファイルをクリック | 保存済みの接続設定をすぐ有効化します。 |
| 各プロファイル右の鉛筆（`Edit`） | ポップアップ内で設定を編集します。編集画面を開くだけでは接続先は切り替わりません。 |
| 状態・接続先 | 有効なプロファイルと競合を確認します。`Regular`は通常ウィンドウ、`Regular + Incognito`はシークレットにも適用する設定です。 |
| `Off` | temotoの上書きを解除し、Chrome・OSやほかの拡張の設定が再び有効になる状態へ戻します。必ず直接接続になるとは限りません。保存したプロファイルは残ります。 |
| 折り畳まれた`Options` | Import、Export、Incognitoの設定を開きます。 |

他の拡張や管理者ポリシーが設定を管理していると、有効化できないことがあります。別の場所で設定を変更した場合は、画面を開き直して状態を確認してください。

## 追加・編集できる設定

| 項目 | 何に使うか |
| --- | --- |
| `Fixed proxy` | Host・Port・種類を指定します。HTTP・HTTPS・SOCKS4・SOCKS5に対応。既存のプロトコル別設定はHTTP宛先・HTTPS宛先・Fallbackも編集できます。 |
| `PAC URL` | 接続経路を決めるPACのHTTP(S) URLを指定します。既存のinline PACはスクリプトを引き続き編集できます。`Block direct fallback`はPACが使えないときの直接接続を止める設定です。 |
| 既存の`Domain routing` | 保存済み・Importしたルールを編集できます。上から順にプロキシ経由か直接接続を判定し、一致しないときの接続方法も指定します。新規追加の最初の選択肢には出ません。 |
| `Direct connections` / `Bypass list` | FixedとDomain routingで、プロキシを通さない宛先を指定します。Domain routingでは個別ルールより先に判定します。PACの場合はスクリプト内で指定します。 |
| `Authentication` | UsernameとSession passwordを入力し、認証先をAllowed proxy hostsへ登録します。許可したプロキシからの認証要求だけに応答します。 |
| `Connection test` | 編集画面から現在有効なプロファイルをテストします。Save & testは編集内容を先に保存してTest URLへ接続します。公開HTTP(S)宛先のみで、リダイレクトは追跡しません。 |
| `Profile actions` | Duplicateは現在保存されている設定を複製します。未保存の編集内容は複製しません。Deleteは画面内で確認して削除し、有効な設定なら先に上書きを解除します。 |

通常の新規追加はFixed proxyとPAC URLに絞っています。既存のDomain routing、プロトコル別接続先、inline PACはEditから元の設定を保ったまま編集でき、従来のJSONもImportできます。

## Save・有効化・Offの違い

- **Save**：使っていないプロファイルを保存します。有効化はホームでそのプロファイルをクリックします。
- **Save & reapply**：現在有効なプロファイルの変更を保存し、その場でChromeへ適用し直します。
- **Cancel**：未保存の編集を破棄します。保存済みの設定は変わりません。
- **Off**：temotoの通常・許可済みシークレット設定の上書きを解除します。プロファイルの削除やOS設定の書き換えは行いません。

編集中にポップアップを閉じた場合、パスワードを除く下書きはブラウザのセッション内に残り、開き直すと復元します。下書きだけでは接続設定は変わりません。

## Optionsと保存内容

| 対象 | 扱い |
| --- | --- |
| Import / Export | 設定をJSONで受け渡します。Exportは認証ユーザー名とパスワードを除きますが、Host・ルール・PACなどは含みます。Importは追加または全置換を選べ、Test URLは標準値に戻ります。全置換は有効な設定とSession passwordを解除します。 |
| Incognito | Chrome側のシークレット使用許可と、Options内での明示的なオンが必要です。Session onlyならシークレットのセッション中だけ適用します。 |
| 保存済みの接続設定・認証ユーザー名 | Chromeの拡張用ローカル保存領域に残ります。 |
| 認証パスワード | セッション保存領域だけに保持します。ブラウザを再起動したら再入力が必要です。下書きとExportには含めません。 |
| 閲覧履歴・通信本文 | 収集・記録する機能はありません。開発者への分析送信もありません。 |

Usernameを変更したらパスワードも入れ直してください。空欄のまま保存すると古い認証情報は解除されます。同じUsernameなら既存のパスワードを保持します。

TestはCookieなどを付けないHEADリクエストで応答を確認します。プロキシ認証は別の仕組みです。出口IPや国を判定する機能はありません。

## 利用の流れ

1. **手元のプロキシで確認する**：プロキシを起動 → `+`でFixed proxyを選ぶ → 実際のHost・Portを入力 → Save → ホームでプロファイルをクリック → 作業後にOff。
2. **会社のPACを使う**：`+`でPAC URLを選ぶ → 指定されたURLを入力してSave → ホームで有効化。既存の細かいルールを変えるときは、そのプロファイルのEditを開きます。

プロキシサーバー自体、VPNサービス、国別IPの接続先は提供しません。使うプロキシや会社のPACは別途用意してください。
